# 3.2.5.1.2 Обработка списка новых или изменённых объектов групповой политики

Для каждого объекта групповой политики (Group Policy Object), входящего в список новых или изменённых объектов групповой политики (как указано в разделе 3.2.1.2), одно сообщение политики реестра (Registry Policy Message) должно быть прочитано с сервера групповой политики, как указано в следующих абзацах. Если какое-либо сообщение не может быть прочитано, последовательность сообщений ДОЛЖНА быть завершена; это означает, что никакие дополнительные сообщения политики реестра не могут быть обменены в течение данного экземпляра последовательности режима применения политики (Policy Application mode sequence).

Следующая последовательность сообщений ДОЛЖНА выполняться для каждого <gpo path>, который, как определил базовый протокол групповой политики (Group Policy: Core Protocol), содержит параметры реестра. Данная последовательность пытается получить сообщение политики реестра для заданного <gpo path>:

1. Для режима политики пользователя (User Policy Mode) абстрактный элемент модели данных Токен имперсонации (Impersonation Token) ДОЛЖЕН использоваться для имперсонации пользователя при всех файловых операциях в данной последовательности.
2. Удалённое открытие файла (Remote File Open) от клиента к серверу: файл, который ДОЛЖЕН использоваться — это "<gpo path>\User\registry.pol" для режима политики пользователя и "<gpo path>\Machine\registry.pol" для режима политики компьютера. Удалённое открытие файла ДОЛЖНО запрашивать разрешение на совместное чтение (Shared Read permission). Если запрос на открытие возвращает статус ошибки, последовательность кодирования расширения реестра групповой политики (Group Policy: Registry Extension Encoding) ДОЛЖНА быть завершена.
3. Последовательности удалённого чтения файла (Remote File Read Sequences): клиент ДОЛЖЕН затем выполнить серию удалённых чтений файла до тех пор, пока не будет получено всё содержимое открытого файла или не произойдёт ошибка. Если происходит ошибка, последовательность кодирования расширения реестра групповой политики ДОЛЖНА быть завершена.
4. Закрытие файла (File Close): клиент ДОЛЖЕН затем выполнить операцию закрытия файла.
5. Для режима политики пользователя имперсонация ДОЛЖНА быть завершена.

После получения всех сообщений клиент ДОЛЖЕН обновить свой реестр в соответствии со следующими указанными правилами. Если проверка подписи файла registry.pol не пройдена, файл является недопустимым и ДОЛЖЕН быть пропущен. Любые ошибки записи в эту базу данных ДОЛЖНЫ игнорироваться. <10> Не существует механизма передачи таких проигнорированных ошибок другим протоколам, поэтому базовый протокол групповой политики (Group Policy: Core Protocol) в целом не будет затронут ошибками при обновлении локальной базы данных.

* Для каждой инструкции (Instruction), найденной в файле, создать ключ базы данных, используя ключ (Key) из инструкции. Под этим ключом создать запись со следующими параметрами:
    * Имя значения (Value Name) из поля Value в инструкции.
    * Тип значения (Value Type) из поля Type в инструкции.
    * Данные (Data), найденные в инструкции для поля DataValue.
* Однако, если имя значения (Value Name) является одним из следующих, необходимо следовать правилам, указанным в таблице вместо этого. Обратите внимание, что имя значения, указанное в таблице, нечувствительно к регистру, но в остальном ДОЛЖНО восприниматься буквально, за исключением случаев, когда указан токен замены в угловых скобках. В этих специальных случаях тип (Type) ДОЛЖЕН быть REG_SZ, за исключением случая SecureKey, где он ДОЛЖЕН быть REG_DWORD, и soft.<valuename>, где тип не ограничен.

| Имя значения | Значение |
| :--- | :--- |
| `**DeleteValues` | Список значений, разделённых точкой с запятой, которые необходимо удалить, указанный в поле DataValue.<br>Пример: В следующем примере удаляются значения EnableURL и TabURL.<br>Ключ: `Software\Policies\Microsoft\Communicator`<br>Имя значения: `**DeleteValues`<br>Тип: `REG_SZ`<br>DataValue: `"EnableURL;TabURL"` |
| `**Del.<valuename>` | Удаляет значение `<valuename>`. В этом случае DataValue игнорируется, но ДОЛЖНО содержать строку, завершённую нулём, с одним символом пробела.<br>Пример: В следующем примере удаляется значение ShowPoliciesOnly.<br>Ключ: `Software\Policies\Microsoft\Windows\Group Policy Editor`<br>Имя значения: `**Del.ShowPoliciesOnly`<br>Тип: `REG_SZ`<br>DataValue: `" "` |
| `**DelVals.` | Удаляет все значения в ключе. В этом случае DataValue игнорируется, но ДОЛЖНО содержать строку, завершённую нулём, с одним символом пробела.<br>Пример: В следующем примере удаляются все значения под ключом Run.<br>Ключ: `Software\Microsoft\Windows\CurrentVersion\Policies\Explorer\Run`<br>Имя значения: `**DelVals.`<br>Тип: `REG_SZ`<br>DataValue: `" "` |
| `**DeleteKeys` | Список ключей, разделённых точкой с запятой, которые являются непосредственными подключами данного ключа и должны быть удалены.<br>Пример: В следующем примере удаляются подключи NoRun и NoFind под ключом Run.<br>Ключ: `Software\Microsoft\Windows\CurrentVersion\Policies\Explorer\Run`<br>Имя значения: `**DeleteKeys`<br>Тип: `REG_SZ`<br>DataValue: `"NoRun;NoFind"` |
| `**SecureKey` | Значение DataValue, равное 1, защищает ключ, предоставляя администраторам и системе полный контроль, а пользователям — доступ только для чтения.<br>Любое другое значение DataValue, кроме указанного выше, сбрасывает доступ к ключу к тому, что установлено в HKCU для пользователя и в HKLM для компьютера.<br>Пример: В следующем примере ключ Run защищён так, что администраторы и система имеют полный контроль, тогда как пользователи имеют доступ только для чтения.<br>Ключ: `Software\Microsoft\Windows\CurrentVersion\Policies\Explorer\Run`<br>Имя значения: `**SecureKey`<br>Тип: `REG_DWORD`<br>DataValue: `1` |
| `**soft.<valuename>` | Создать значение `<valuename>`, только если оно не существует.<br>1. Пример: В этом примере значение ApplyPolicies создаётся только если значение ApplyPolicies не существует.<br>Ключ: `Software\Policies\Microsoft\Windows\Group Policy Editor`<br>Имя значения: `**soft.ApplyPolicies`<br>Тип: `REG_DWORD`<br>DataValue: `1`<br>2. Пример: В этом примере значение RootPath создаётся только если значение RootPath не существует.<br>Ключ: `Software\Policies\Microsoft\Windows\Group Policy Editor`<br>Имя значения: `**soft.RootPath`<br>Тип: `REG_SZ`<br>DataValue: `%PROGRAMFILES%` |

* Элементы инструкции (Instruction) ДОЛЖНЫ обрабатываться в том порядке, в котором они встречаются, последовательно от начала сообщения политики реестра. Необходимость этого демонстрируется примером, в котором одна инструкция требует установить значение базы данных в 1, а другая инструкция требует установить его в 0. В зависимости от порядка выполнения этих инструкций итоговое значение будет либо 1, либо 0. Для обеспечения предсказуемой работы инструкции ДОЛЖНЫ выполняться последовательно, начиная с первой инструкции в сообщении политики реестра.
